# Подготовка к публикации

Публикуемый набор состоит из исходников, конфигурации без рабочих секретов, документации, четырёх вымышленных документов и трёх просмотренных снимков учебного интерфейса.

## Проверка состава файлов

В папке репозитория при установленном Node.js 20 или новее выполните следующие команды.

```powershell
node --test scripts/check-publication.test.mjs
node scripts/check-publication.mjs
git ls-files --cached --others --exclude-standard
```

Проверка учитывает подготовленные к коммиту и новые файлы. Даже принудительно добавленные через `git add -f` секреты и документы отклоняются по типу и расположению. Символические ссылки также отклоняются. В сообщениях выводятся имена проблемных файлов, содержимое секретов не печатается.

`.gitignore` исключает `.env`, `.local`, ключи, базы, дампы, архивы, пользовательские офисные документы и автоматически созданные отчёты/снимки. Из DOCX/PDF разрешены ровно четыре файла `frontend/e2e/fixtures/synthetic-*`, перечисленные явно. Из PNG разрешены три учебных экрана, указанные в `.gitignore` и скрипте проверки. Материалы, исключённые из Git, сохраняются на диске владельца установки.

Содержимое документов проверяется через `scripts/verify_public_fixtures.py`. Для DOCX сверяются все файлы внутри контейнера ZIP с синтетическим генератором, для PDF — все байты. Проверка встроена в GitHub Actions после сборки backend.

Для отдельной копии только публикуемых файлов выполните следующую команду. Она создаёт новый каталог внутри игнорируемой `.local`, печатает его путь и сохраняет список файлов с SHA-256.

```powershell
node scripts/check-publication.mjs --export
```

## Проверка содержимого на секреты

Запустите Gitleaks по созданной копии. Вместо `ПУТЬ_ИЗ_ПОЛЯ_SOURCE` вставьте путь, напечатанный предыдущей командой. Для запуска нужен Docker Desktop.

```powershell
$publicationSource = 'ПУТЬ_ИЗ_ПОЛЯ_SOURCE'
./scripts/docker.ps1 run --rm --network none -v "${publicationSource}:/repo:ro" ghcr.io/gitleaks/gitleaks@sha256:c00b6bd0aeb3071cbcb79009cb16a60dd9e0a7c60e2be9ab65d25e6bc8abbb7f dir /repo --config /repo/.gitleaks.toml --redact --no-banner
```

Ожидается успешный код выхода и сообщение `no leaks found`. Автоматическая проверка распознаёт известные форматы секретов. Перед каждым коммитом просмотрите содержимое изменений через `git diff --cached`, особенно свободный текст и новые изображения. В `.env.example` допустимы только образцы и пустые значения для ключей.

## Чистая установка и учебный пример

Проверять первый запуск следует в новой папке и с отдельной базой по [SETUP_WINDOWS.md](SETUP_WINDOWS.md). Сценарий проверки доступен в [DEMO_WALKTHROUGH.md](DEMO_WALKTHROUGH.md). При подготовке текущей версии используется отдельный Compose-проект с собственными секретами, образами, томами и портом. Рабочие данные проверяются до и после по контрольным хешам.

GitHub Actions выполняет сборку по lock-файлам, тесты frontend/backend, проверку синтетических документов, Gitleaks, аудит зависимостей и браузерные сценарии. Фактический результат GitHub Actions появляется после запуска workflow на GitHub. Локальный прогон фиксируется в [PROGRESS.md](PROGRESS.md).

## Лицензия и размещение

Лицензию авторского кода выбирает владелец проекта. Сведения о сторонних компонентах и их лицензиях находятся в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Перед публикацией нужно завершить выбор лицензии.

GitHub хранит исходники и инструкции. Для общего рабочего сайта потребуется отдельное серверное размещение, настройка HTTPS, доступа и резервного копирования. Учебные аккаунты содержат вымышленные сведения. Для корпоративного экземпляра администратор назначает права реальным пользователям и определяет правила обращения с документами.
