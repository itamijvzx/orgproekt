# Технические журналы OrgProekt на Windows

## Автоматическая ротация

Для служб проекта задан Docker logging driver `local`: `max-size: 10m`, `max-file: 3`, `compress: true`. Docker автоматически меняет файл при достижении размера и удаляет самые старые технические журналы сверх трёх. Для каждого контейнера это ориентир до 30 МБ сообщений до сжатия, а не общий лимит диска для Docker.

Политика задана в `compose.yml`, `compose.test.yml`, `compose.e2e.yml` и самостоятельном `compose.restore.yml`. У шести работающих основных служб она уже применена. Тестовые/операторские профили и новый стенд восстановления получат её при создании контейнеров. Отдельный процесс очистки и запуск Codex не требуются.

Ограничение относится к stdout/stderr контейнеров. Аудит в PostgreSQL, документы, предложения, выпущенные отчёты, резервные копии и ключи имеют собственное хранение. Размер образов, постоянных томов, WSL-диска и журналов самого Docker Desktop этой настройкой не ограничивается.

## Проверка

В Windows PowerShell с доступной командой `docker`, из любой папки:

```powershell
docker inspect orgproekt-api-1 --format '{{json .HostConfig.LogConfig}}'
```

Ожидается тип `local` и параметры `max-size=10m`, `max-file=3`, `compress=true`. Команда показывает только настройки логирования, не переменные среды с секретами. Полный `docker inspect` для публикации не используйте.

Посмотреть последние 50 сообщений API:

```powershell
docker logs --tail 50 orgproekt-api-1
```

В Docker Desktop те же сообщения доступны в **Containers → orgproekt → api → Logs**. Внутренние файлы драйвера Docker вручную не редактируют и не удаляют.

Изменение `logging` в Compose действует на вновь созданные контейнеры. Чтобы применить новые лимиты к уже работающим службам, нужен их контролируемый перезапуск с сохранением томов. На этом компьютере он уже выполнен: повторять команды обновления ради проверки не требуется.

Проверено 31.10.2026: итоговые Compose-конфигурации всех профилей корректны; работающие API, Caddy, PostgreSQL, RabbitMQ, worker и scheduler используют заданные лимиты. До обновления создана проверенная зашифрованная копия; после него совпали все 915 строк в 50 таблицах, схема и необходимые секретные файлы. Образы и имена постоянных томов прежние. `/api/health` вернул `ok`, страница входа после обновления открылась в браузере.

Первичные материалы: [Docker local logging driver](https://docs.docker.com/engine/logging/drivers/local/), [применение настроек к контейнерам](https://docs.docker.com/engine/logging/configure/).
