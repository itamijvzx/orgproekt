# Проверка установки и нагрузки на Windows — 10.11.2026

Проверка выполнена на отдельной учебной копии, созданной из опубликованного коммита `8e76f3d` на GitHub. У копии были собственные база данных, очередь, тома и адрес `http://orgproekt.localhost:18080`. Основной сайт на 8080 оставался доступен. Новая установка создала 26 сотрудников в пяти отделах и 45 учебных документов. Вход аудитора, видимость документов, ограничение ИТ своим отделом, отказ в доступе к чужому документу и защита CSRF прошли проверку через API. Учебный пароль и секреты из этой установки в репозиторий не записывались.

## Условия нагрузочной проверки

Клиенты использовали один учебный сеанс аудитора и только чтение: попеременно `GET /api/v1/organization` и `GET /api/v1/documents?offset=0&limit=10`. Каждый виртуальный клиент отправлял примерно один запрос в секунду в течение 15 секунд. Тест шёл на этом же ПК через отдельный стек Docker; основной сайт проверялся на доступность между ступенями. Подготовка данных, загрузка файлов, сравнения, поиск и отчёты в нагрузку не входили.

| 5 | 75 из 75 | 4,9 запр./с | 35 мс | 54 мс |

| 30 | 450 из 450 | 28,3 запр./с | 378 мс | 394 мс |
| 40 | 459 из 459 | 28,6 запр./с | 1563 мс | 2304 мс |

На ступени 30 клиентов CPU тестового API был около 73%, базы — 21%; память API — около 118 МиБ при лимите 2 ГиБ. На 40 клиентах скорость перестала расти, а время ответа резко увеличилось. Тест остановлен на этой ступени. Ошибок HTTP в указанной выборке не было.

Это **не предел числа зарегистрированных или одновременно открывших сайт людей**. Проверка моделирует активные запросы одного аккаунта к двум маршрутам. Реальные пользователи делают паузы, но загрузка DOCX/PDF, построение индекса, сравнения и массовые изменения могут потреблять намного больше CPU и памяти. Для конкретной компании нужны отдельные испытания на её оборудовании, с её объёмом документов, числом уникальных аккаунтов и обычными сценариями работы.

Рабочий ориентир для этого ПК и только для указанного чтения: 20 активных клиентов при одном запросе в секунду обслуживались быстро; на 30 задержка выросла; на 40 стек достиг насыщения. Основной сайт оставался доступен. Изолированная копия после проверки остановлена.
