# Локальный учебный режим

Для знакомства на своём компьютере новая установка через `scripts/setup.ps1` или `scripts/setup_env.py` создаёт `.env` с `LOCAL_DEMO_MODE=true`. Вход выполняется по личному логину и паролю. Телефон, Google Authenticator и Windows Hello не требуются. Подпись режима видна на странице входа и в рабочем пространстве.

Права пользователей, границы отделов, история, защита от подбора пароля, CSRF и срок сессии сохраняются. Сеанс завершается после 30 минут бездействия; фоновое обновление страницы не продлевает его. При активном вводе браузер подтверждает сеанс раз в минуту, а за пять минут до завершения предупреждает сохранить черновик. Общий срок сеанса — не более 8 часов, он не продлевается активностью. Важные действия после десяти минут требуют повторно ввести пароль. Существующие секреты MFA и резервные коды не удаляются и не расходуются. Замена/подключение MFA в этом режиме недоступны.

## Границы режима

Режим предназначен только для вымышленных документов на локальном компьютере. Стандартный адрес — `http://orgproekt.localhost:8080`; сервер допускает точные HTTP-origin `orgproekt.localhost`, `localhost`, `127.0.0.1` или `::1` для отдельных локальных стендов, без пути и параметров URL. Старый адрес `localhost:8080` перенаправляет на стандартный и очищает прежний cookie. В Compose опубликован только Caddy на `127.0.0.1`; не меняйте это на `0.0.0.0`, не подключайте туннели и публичный reverse proxy. API отклоняет чужой Host и Origin. Внешний Gemini и ключи доступа в этом режиме отключены.

Учебный вход имеет отдельную отметку в сессии и аудите. Он не считается пройденной MFA. После отключения режима такие сессии больше не дают доступа к бизнес-API; фоновая обработка также повторно проверяет политику и текущие права.

## Новая и существующая установка

Новый пользователь выполняет команды из [SETUP_WINDOWS.md](SETUP_WINDOWS.md), затем проходит [DEMO_WALKTHROUGH.md](DEMO_WALKTHROUGH.md). Пароли генерируются отдельно для каждой установки.

`setup.ps1` не перезаписывает существующую `.env`. При отсутствии `LOCAL_DEMO_MODE` действует обязательная MFA. Чтобы вернуть её на новой учебной установке, задайте `LOCAL_DEMO_MODE=false` в её `.env` и выполните `./scripts/docker.ps1 compose up -d --wait`. Войдите заново и настройте MFA либо используйте ранее подключённый фактор. Для обработки заданий, оставшихся от учебной сессии, может потребоваться повтор после нового входа.

Не включайте режим без MFA на базе с настоящими данными. Для изучения используйте отдельную установку с собственной пустой базой. Текущая база владельца проекта и её настройки при разработке этого режима не переключаются.

## Резервное копирование по желанию

Обычная установка не создаёт задание Планировщика Windows и не делает автоматических архивов. Ручное копирование, создание recovery-ключа и включение расписания описаны в [BACKUP_RESTORE_WINDOWS.md](BACKUP_RESTORE_WINDOWS.md). Доступно ежедневное расписание с хранением трёх последних автоматических копий.

Если расписание ранее было установлено на вашем компьютере, оно продолжает работать независимо от режима входа. Для его удаления вручную, из папки проекта:

```powershell
./scripts/backup-schedule.ps1 -Action Remove
```

Команда сохраняет уже созданные архивы и ключ. Самостоятельно установленные задания других пользователей проект не изменяет.

Восстановительные стенды по умолчанию требуют MFA и отзывают перенесённые сессии. Сохранённые факторы продолжают действовать; если фактор ещё не подключён, его потребуется настроить при первом входе в восстановленную копию.

## Проверки

`./scripts/e2e.ps1` проверяет обычный режим с MFA; `./scripts/e2e.ps1 -LocalDemo` — учебный вход и тот же цикл работы без второго фактора. Оба используют отдельный одноразовый проект `orgproekt-e2e`. Запускайте последовательно. Эти команды не переключают режим действующего сайта. Дополнительные серверные тесты находятся в `backend/tests/test_local_demo.py`.
