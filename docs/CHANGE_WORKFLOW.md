# Предложения, обсуждение и согласование

В локальном учебном режиме (`LOCAL_DEMO_MODE=true`) вход выполняется без MFA. В шагах ниже пропускайте настройку и ввод второго фактора; при повторном подтверждении нужен только пароль. Права и согласования сохраняются. [Подробнее о режимах](LOCAL_DEMO.md).

## Как пользоваться

Откройте **Изменения → Предложения** в верхнем меню. На узком экране раздел находится в общем меню. Аудитор также может выбрать вопрос в рабочем обзоре и нажать **Подготовить предложение**: функция и её документальное основание будут подставлены в форму.

1. Аудитор создаёт предложение: название, дата проектной модели и разделы затронутых подразделений. Для каждого действия указываются объект, вид изменения, состояние «до» и «после», обоснование и точные источники. Таблица является проектом, а не утверждением об изменении действующего реестра.
2. Перед отправкой проверьте последствия и документы. При выборе кандидата нужны документированные требования, сведения о квалификации и источники. Отсутствие сведений не доказывает отсутствие навыка. Автоматического подбора или назначения нет.
3. Явно выберите адресатов и срок. Пригласите представителей каждого отдела и руководителя с полномочиями по всем затронутым разделам; для последующего исполнения нужен уполномоченный HR. Участие в предложении не расширяет текущие права на отдел.
4. Адресаты открывают предложение из списка или уведомления. Во вкладке обсуждения сохраняются сообщения и ссылки на документы. Ответ согласующего — отдельное действие: согласовать, вернуть, отклонить или запросить сведения. Прочтение и обычный комментарий не являются согласием.
5. Для содержательных исправлений аудитор создаёт новую версию с причиной изменения и направляет её заново. Старые версии, ответы и решения сохраняются; их согласование не применяется к новой редакции.
6. Уполномоченный руководитель принимает отдельное мотивированное решение. Автор не может утвердить собственное предложение. Принятие риска фиксируется отдельно и не означает исполнение.
7. HR фиксирует план или подтверждённое исполнение конкретного действия. Для завершения нужны действующая дата и официальное основание. Временное замещение подтверждается подходящим официальным кадровым событием. Будущее действие можно только запланировать.
8. После выполнения всех действий аудитор отдельно проверяет исполнение. Частичное выполнение и оставшиеся действия видны в истории.

Закрытая заметка автора хранится отдельно от общего обсуждения. Она не становится сообщением при отправке предложения. Уведомления показывают доставку и прочтение; сроки, ответы, напоминания и эскалации привязаны к определённой версии.

До фактического исполнения автор может мотивированно отменить предложение. Отмена сохраняет версии и ответы. Она не отменяет уже зарегистрированные кадровые события.

## Учебные роли

На чистой установке команда `workflow-demo` создаёт `demo_manager` — **Роман Берёзов · учебный руководитель** — и `demo_reviewer`. Пароли находятся в `.local/workflow-accounts.json`; при первом входе настройте MFA. Для проверки цикла аудитор направляет предложение руководителю, руководитель принимает решение, `hr` регистрирует исполнение, аудитор проверяет результат. Руководителя нужно явно пригласить в каждый затронутый раздел. Если версия уже направлялась другим участникам, добавляйте только ещё не приглашённых адресатов. Файл и аккаунты повторным запуском не перезаписываются.

Прежние учётные записи и их права сохраняются. Для демонстрации управленческого решения предусмотрена отдельная операторская команда:

```powershell
./scripts/docker.ps1 compose -p orgproekt -f compose.yml --profile tools run --rm tools python -m app.cli workflow-demo
```

Она работает только на существующем учебном стенде в `development`, добавляет `demo_manager` и `demo_reviewer` с отдельными случайными паролями и записывает событие безопасности. Чтобы создать только руководителя, используйте:

```powershell
./scripts/docker.ps1 compose -p orgproekt -f compose.yml --profile tools run --rm tools python -m app.cli workflow-demo --username demo_manager
```

Параметр выбирает только заранее определённый учебный аккаунт. Пароли сохраняются локально в `.local/workflow-accounts.json`. При первом входе подключите MFA. Повторный запуск сохраняет существующие аккаунты и файл. Для обычного управления пользователями используется раздел [«Доступ»](ACCESS_WORKFLOW.md).

## Границы реализации

- Проект хранит версионные действия, источники и последствия; он не подменяет действующую организацию. Подтверждение исполнения по документу является записью HR с последующей проверкой аудитора. Редактирование штатной структуры и реестра функций по всем видам проекта автоматически не выполняется. Официальные кадровые назначения регистрируются в существующем кадровом процессе.
- Обсуждения и согласование работают внутри приложения. Внешняя почта и мессенджеры не подключены.
- Gemini для этого процесса не используется; ключ не требуется. Поля квалификаций служат доказательному рассмотрению человеком, не машинному ранжированию сотрудников.
- Источники выбираются из уже доступных редакций. Загрузка новых вложений выполняется через раздел «Документы» с последующим добавлением ссылки на точную выдержку.
- Production TLS, управляемый LangGraph, итоговые PDF/DOCX-отчёты и полный цикл эксплуатации не объявляются завершёнными этим этапом.
