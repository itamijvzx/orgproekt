# Рабочие и тестовые образы OrgProekt

Рабочие службы используют отдельную сборку без инструментов разработки. Версии прикладных зависимостей берутся из прежнего `backend/uv.lock`; разделение не меняет схему БД, API или права доступа.

## Состав и сборка

| Образ | Назначение | Содержимое |
|---|---|---|
| `orgproekt-backend:local` | API, обработчик файлов, worker, scheduler, миграции и обычные служебные команды | Runtime-зависимости, приложение, миграции, операции backup, шрифты и проверенная локальная модель поиска |
| `orgproekt-backend-test:local` | Pytest, Ruff, pip-audit и подготовка одноразовых E2E-данных | Рабочая сборка плюс dev-группа того же lock-файла, тесты и вспомогательные скрипты |
| `orgproekt-backup:local` | Шифрованное копирование и восстановление | Рабочая сборка плюс age и PostgreSQL client |
| `orgproekt-backup-test:local` | Проверка шифрования и отказов восстановления | Backup плюс dev-зависимости; не используется ежедневным заданием копирования |

`backend/Dockerfile` и `tools/backup/Dockerfile` по умолчанию собирают stage `production`. Для тестов используется явный `--target test`. Stage с тестами не является родительским слоем рабочего образа. Бинарный файл uv подключается временно при сборке; в рабочий образ не копируется. Подход основан на [документации uv для Docker](https://docs.astral.sh/uv/guides/integration/docker/#using-uv-temporarily).

В рабочем `/app` отсутствуют `tests`, `scripts`, `pyproject.toml` и `uv.lock`. Зарегистрированные пароли, MFA, документы и роли хранятся в прежних томах/секретах, а не в этих файлах. Для операций вроде экспорта OpenAPI скрипт по-прежнему читается из подключённого исходного репозитория.

Обычный запуск приложения остаётся прежним. Для серверных тестов:

```powershell
./scripts/docker.ps1 compose -f compose.yml -f compose.test.yml --profile tests run --build --rm tests
```

Тесты создают и удаляют только отдельную БД `orgproekt_test_*`. `scripts/e2e.ps1` сам собирает тестовый образ для инструментов и запускает одноразовый проект `orgproekt-e2e`. Проверка HTTPS/passkeys также собирает отдельный тестовый образ; служебный образ визуальной проверки отчётов получает uv только на время установки своих дополнительных зависимостей.

## Контроль состава в CI

`scripts/check_runtime_image.py` запускается внутри настоящих backend/backup-образов. Он проверяет отсутствие pytest, Ruff, pip-audit, virtualenv, uv и тестовых исходников; наличие необходимых файлов/модели, импорт основных библиотек и запуск от непривилегированного пользователя.

Контроль проверен и на отрицательном примере: прежний образ с инструментами разработки отклоняется. Новые рабочие образы проходят проверку. `pip-audit` выполняется в тестовом окружении с тем же lock-файлом, охватывающем и рабочие зависимости. Trivy продолжает сканировать именно пять рабочих образов; правила обработки предупреждений не ослаблены.

## Измерения 11 ноября 2026 года

| Показатель | До разделения | После |
|---|---:|---:|
| Backend, размер по Docker | 1 082,8 МБ | 929,3 МБ |
| Backup, размер по Docker | 1 173,9 МБ | 1 020,4 МБ |
| Установленные Python-дистрибуции рабочего окружения | 107 | 83 |

Каждый рабочий образ уменьшился примерно на 153,5 МБ: backend на 14,2%, backup на 13,1%. Указан распакованный размер, МБ = 1 000 000 байт. Docker переиспользует общие слои; фактическое место на ПК также зависит от кеша сборки и сохранённых образов отката.

Проверки новой сборки: backend **167 passed, 5 skipped**; backup с age **18 passed**; Chromium с MFA и local demo **12 passed, 1 ожидаемый skip**. Пропущенные backend-проверки требуют age и выполняются в отдельном backup-наборе. Проверены роли, приглашения и отзыв доступа, сохранение изменений, обработка документов, согласование, отчёты PDF/DOCX и ошибочный ввод. Ruff, OpenAPI, pip-audit, правила Trivy и синтаксис конфигураций прошли проверку. Полные интерактивные сценарии Windows Hello и LibreOffice повторно не запускались.

Коммит `9bf872b` с предыдущими исправлениями опубликован в `codex/github-security`; его [GitHub Actions завершился успешно](https://github.com/itamijvzx/orgproekt/actions/runs/42974559620). Разделение образов является следующей локальной доработкой: её собственный удалённый прогон возможен после согласованных коммита и отправки.

## Обновление текущего сайта

Перед переключением создана проверенная шифрованная копия; прежние образы сохранены для отката. После обновления совпали отпечатки всех **52 таблиц и схемы**. Сохранены **8 аккаунтов, 24 назначения прав и 47 редакций документов**, секретные файлы и существующая обязательная MFA. Цепочка аудита валидна, 326 записей. PostgreSQL, RabbitMQ и Caddy не пересоздавались для этой доработки.

Новое средство backup создало ещё одну проверенную копию. Её восстановление на отдельном стенде подтвердило 52 таблицы/915 строк, схему и привилегии, контрольные суммы файлов и цепочку аудита. Семь скопированных сессий отозваны только в восстановленной копии. Тестовый и восстановленный стенды со своими томами удалены; основной сайт отвечает `status: ok`. Задание резервного копирования Windows и его политика хранения не менялись.

Приватные подтверждения находятся в `.local/runtime-split-20261111/` и не входят в Git. Состав будущей публикации проверяется отдельно от рабочих данных.

## Оставшиеся предупреждения

Удаление инструментов разработки уменьшило размер и число установленных пакетов. Число HIGH/CRITICAL-совпадений Trivy для backend и backup осталось прежним: соответственно **47** и **106** записей без указанного исправления поставщика, плюс по пять проверенных записей только из build SBOM. Новых необработанных совпадений с доступным исправлением нет. В новом runtime msgpack отсутствует; старая запись о нём остаётся только во вложенном описании сборки сторонней библиотеки. Точное исключение обновлено с сохранением срока 11.12.2026.

Три CRITICAL-совпадения PostgreSQL дополнительно сопоставлены с первичными источниками:

- **CVE-2025-7458, SQLite.** Debian bookworm отмечен уязвимым, обновление по отдельному security advisory не планируется (`no-dsa`, minor issue). Описанный сценарий требует выполнения специально составленного SQL в SQLite. Приложение использует PostgreSQL; обращений приложения к SQLite при поиске исходников не найдено. Это оценка достижимости, а не доказательство отсутствия любых других путей. [Debian](https://security-tracker.debian.org/tracker/CVE-2025-7458).
- **CVE-2026-6653, libxml2.** Для bookworm исправление отложено как minor issue. В SQL-коде приложения не найден вызов XML-парсера PostgreSQL; библиотека остаётся частью возможностей самой БД. Её произвольная замена или смена ОС базового образа требует отдельной проверки совместимости и восстановления. [Debian](https://security-tracker.debian.org/tracker/CVE-2026-6653).
- **CVE-2023-45853, MiniZip.** Debian поясняет, что уязвимый contrib-компонент не собирается из zlib для bookworm. [Debian](https://security-tracker.debian.org/tracker/CVE-2023-45853).

Образ PostgreSQL в этой доработке не менялся. Предупреждения не удалены из сырых отчётов и не превращены в разрешение внешней эксплуатации. Существующая изоляция сети, ограничения ресурсов, серверные права и проверка входных данных сохранены.
