# OrgProekt: визуальная система

Локальный учебный режим сохраняет центрированную форму и текущие компоненты shadcn/ui. Первое действие — личный логин/пароль; рядом видна подпись «MFA отключена». В рабочем пространстве остаётся короткая пометка режима. В формах подтверждения скрывается только поле второго фактора, пароль остаётся. Списки, поиск, действия и права не меняются. Критерий проверки: вход, ошибка пароля, повторное подтверждение, сохранение после reload и читаемость на 1440/390 px; без новых декоративных блоков.

## Доступ — дополнение 30.10.2026

Пользователь `access` приглашает личный аккаунт и оформляет обоснованный запрос; manager проверяет роль, отдел и срок. Первый объект — пользователь/ожидающий запрос, основное действие — приглашение или решение. Четыре вкладки администратора: пользователи, приглашения, назначения на подтверждении, история доступа. Manager видит только очередь своей области через «Ещё → Доступ». Для технического администратора скрыта предметная навигация; «Моё пространство» сохраняет собственные настройки безопасности.

Переиспользованы три существующих паттерна OrgProekt: каталог документов → таблица пользователей с поиском/пагинацией; адресное согласование предложения → отдельное решение руководителя с основанием; история отчёта → журнал изменений доступа. Формы создаются из shadcn/ui, используют прежние тёмные поверхности, Manrope, зелёные действия, доступные подписи и focus ring. Успешная отправка запроса не выглядит как уже действующая роль. Конфликт оставляет введённый текст, reauth встроена рядом с действием. Приглашение активируется в одной центрированной форме входа; код показывается только в отдельном закрываемом диалоге.

Finish gate PASS в проверенных состояниях Chromium 1440/390, снимки 51–56. Наблюдаемая проблема: кнопка отзыва находилась за правой границей таблицы на телефоне. Исправление: назначения превращаются в вертикальные группы с подписями полей; кнопка и основание видимы в пределах 390 px, что проверяется bounding box в e2e. Просмотрены приглашение/запрос/решение/действующая роль/история, загрузка и пустые состояния; ошибка options и конфликт проверены Vitest. Декоративные KPI, новый стиль и новые библиотеки не добавлены. Полный WCAG/screen-reader аудит не заявляется.

## Отчёты — дополнение 30.10.2026

Пользователь: аудитор готовит сообщение на документальных основаниях; reviewer проверяет конкретную редакцию; адресат читает выпущенный результат. Первый объект — название, состояние и номер редакции. Список с поиском/состоянием служит очередью, форма содержит два столбца смысловых полей на desktop и один на узком экране. Источники, прошлые редакции и текущий реестр раскрываются отдельно. В состоянии released доступны файлы и связанное исправление, редактирование отсутствует.

Переиспользованы паттерны существующих экранов: таблица документов, процессная форма предложения, список истории и диалог источника. Сохранены фон/панели/зелёные действия/Manrope/верхняя навигация; у textarea явные доступные имена, контрастная граница и прежний focus ring. Заголовок отчёта 22px; длинные названия и хеши переносятся без общей горизонтальной прокрутки. Нет декоративных KPI, нового лендинга или имитации содержимого.

Finish gate для этого среза: PASS по наблюдаемым состояниям Chromium 1440/390, созданию/возврату/выпуску/скачиванию и отсутствию overflow/JS errors. Снимки 41–43. Это не полный аудит WCAG или screen-reader. Экспорт — белая печатная страница, чёрный текст DejaVu Sans, выделенные заголовки, защищённые ссылки и номера страниц; показано всё содержание проверенной редакции. PDF/DOCX могут иметь разные переносы, но одинаковый текст.

Действующее направление от 29.10.2026 — согласованный пользовательский макет «Рабочий обзор внутреннего аудита»: черный фон, графитовые панели, зеленые действия, верхняя навигация. Оно заменяет прежнюю светлую палитру, боковое меню и значок рядом с названием. Все элементы — настоящие компоненты с данными API; изображение не используется как фон.

## Композиция и сценарий

Пользователь выбирает вопрос покрытия, сверяет состояние функции на дату, открывает точное основание и переходит к разрешенному кадровому действию. Первый объект — вопрос, основное действие страницы — сравнение документов.

Рабочая ширина до 1320 px, внешняя рамка 1368 px с боковыми отступами 24 px. Шапка 64 px и содержимое выровнены. Верхнее меню: обзор, организация, документы, изменения, журнал. В «Изменениях» — предложения, комплекты/сравнение и кадровые события; в «Ещё» — реестр функций, поиск, сведения о проекте. Справа уведомления и меню пользователя с ролью. Ниже 960 px разделы открываются во временном Sheet; постоянного левого меню нет.

Обзор: общая панель вкладок, поиска и отдела; колонки списка/подробностей 38/62. Карточка содержит состояние, вопрос, название функции, отдел. Правая область показывает функцию, статус, сведения реестра, точную цитату, историю покрытия и доступные переходы. Смена вопроса/даты/фильтра скрывает прежние сведения до ответа API. Фильтры сохраняются в Zustand при переходах и сбрасываются при выходе. На узком экране список и подробности идут последовательно.

Вкладки обзора соответствуют API покрытия: «Все вопросы», «Нет исполнителя», «Недостаточно данных». Действие «Подготовить предложение» открывает настоящий процесс с выбранной функцией и источником. Согласования и обсуждения находятся в разделе «Изменения → Предложения». Последние события относятся ко всем доступным подразделениям независимо от даты/фильтра вопросов; это указано рядом.

Организация, сотрудники, функции, документы — таблицы и фильтры; сравнение — связанные источники «до/после»; кадровые события — хронология; журнал — время, автор, действие, объект и результат. React Flow остается дополнительным режимом организации. Декоративные графики и дополнительные деревья не добавлены. Вход/MFA — одна центрированная колонка до 420 px.

## Предложения и согласование

Список предложений использует поиск, фильтры состояния/отдела и пагинацию. Карточка показывает версию, состояние и вкладки проекта, обсуждения, согласования, исполнения и истории; личные заметки доступны только автору. Действия опираются на серверные права. Прочтение уведомления, ответ, согласие, управленческое решение, исполнение и проверка аудитора имеют отдельные подписи и записи.

Формы ответа и решения находятся перед предыдущими ответами. Несохранённый ввод сохраняется при смене вкладок и фоновом обновлении, конфликт 409 оставляет форму открытой. При смене версии или отзыве доступа прежние поля удаляются. Источники выбираются по документу и локатору; проектная модель «до/после» отделена от официального реестра.

На 390 px сетка перестраивается в одну колонку, поля и кнопки переносятся без горизонтального переполнения страницы; длинная строка вкладок прокручивается локально. Поверхности, палитра, типографика и обязательные библиотеки остаются прежними. Визуальная приёмка этапа 3: снимки 31–36, 1440/390 px, Finish-Gate PASS в проверенных состояниях.

## Название и библиотеки

Отображаемое название использует существующий `organization/settings`: незаполненное значение дает **OrgProekt**, введенное название появляется в шапке после сохранения. Fallback находится в `lib/branding.ts`. Вход до авторизации показывает публичное название продукта. Исторические источники не переименовываются. Отметка учебных данных остается внизу рабочего пространства.

- shadcn/ui: Button, Input, Label, Dialog, Sheet, Tabs, Badge, Table, Sonner. Меню на уже установленном Radix UI поддерживают клавиатуру и возврат фокуса.
- React Flow: узлы отделов/должностей/единиц/назначений, поиск, раскрытие, инспектор. Тема включает контролы, связи и сетку.
- Motion: короткие переходы содержимого/инспектора, `MotionConfig reducedMotion="user"`.
- Бесплатный Magic UI Shimmer Button: вход/подтверждение, темная надпись на зеленом. Эффект только при наведении/фокусе, выключается при reduced motion и не изображает серверный прогресс.
