# Windows 11: локальный стенд

Новая установка по этой инструкции использует локальный учебный режим: **MFA отключена для удобства знакомства, автоматическое резервное копирование не включается**. Входите по логину и паролю. Ручные копии и расписание доступны по желанию. Существующая `.env` и ранее установленное расписание сохраняются. Подробности — [LOCAL_DEMO.md](LOCAL_DEMO.md).

Потребуются Windows 11, Docker Desktop с WSL 2 и Git. Запустите Docker Desktop и дождитесь готовности Linux engine. Скачайте репозиторий через Git или **Code → Download ZIP**, распакуйте его и откройте PowerShell в папке с `compose.yml`. Сборка приложения выполняется в Linux-контейнерах. На первом запуске нужен интернет для образов, зависимостей и модели поиска.

Если PowerShell сообщает, что выполнение сценариев запрещено, выполните `Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned` в текущем окне. При загрузке ZIP убедитесь, что архив получен из нужного репозитория, снимите отметку блокировки в свойствах архива Windows и распакуйте его заново.

Следующие команды предназначены для первой установки с пустой базой.

```powershell
./scripts/docker.ps1 version
./scripts/docker.ps1 compose version
./scripts/setup.ps1
./scripts/docker.ps1 compose up -d --build --wait
./scripts/docker.ps1 compose --profile tools run --rm tools python -m app.cli seed
./scripts/docker.ps1 compose --profile tools run --rm tools python -m app.cli expand-demo
./scripts/docker.ps1 compose --profile tools run --rm tools python -m app.cli workflow-demo
Invoke-RestMethod http://orgproekt.localhost:8080/api/health
```

`setup.ps1` создаёт случайные секреты в `.env` и сохраняет уже существующий файл. `seed` допускается только в development и на пустой базе. `expand-demo` добавляет учебный состав из 26 сотрудников в пяти подразделениях. `workflow-demo` добавляет учебных руководителя и рецензента. Для повторного запуска заполненной установки выполните только `./scripts/docker.ps1 compose up -d --wait`. Отказ повторного `seed` означает, что база уже содержит данные.

После установки пройдите [учебный пример](DEMO_WALKTHROUGH.md). Он показывает конкретные файлы, значения полей, кнопки и ожидаемые результаты.

Успех: `/api/health` возвращает `status: ok`, `compose ps` показывает здоровые db/api/rabbitmq/parser/worker; migrate завершается с кодом 0. Откройте [orgproekt.localhost:8080](http://orgproekt.localhost:8080). Используйте именно этот адрес: Origin должен совпадать с `.env`.

## Первый вход

Начните с `auditor`. Его пароль находится в `.local/demo-accounts.json` в записи `accounts` → `auditor` → `password`. Пароли `demo_manager` и `demo_reviewer` после `workflow-demo` находятся в `.local/workflow-accounts.json`. Под `access` автоматически открывается раздел **«Доступ»**. Полный сценарий приглашения и назначения прав приведён в [ACCESS_WORKFLOW.md](ACCESS_WORKFLOW.md).

Личные учебные аккаунты и уникальные пароли — в `.local/demo-accounts.json`; открыть локально, не копировать в чат/коммит. `auditor` исследует пять отделов, `hr` регистрирует события, `it` и `finance` видят свой отдел. `access` имеет доступ к журналу безопасности, без бизнес-данных. Это разные синтетические личности, а не выбор роли на экране входа.

При `LOCAL_DEMO_MODE=true` после пароля сразу открывается рабочее пространство. Если параметр отсутствует или равен `false`, после пароля обязательны настройка TOTP и сохранение восьми резервных кодов. QR обрабатывается локально, сторонний QR-сервис не используется. Повтор одного TOTP отклоняется: дождитесь следующего кода. Часы компьютера и аутентификатора должны быть синхронизированы. MFA владельца основного стенда автоматические тесты не настраивают.

Повторное подтверждение находится в «Моё пространство» и действует 10 минут для чувствительных действий: в учебном режиме нужен пароль, в режиме с MFA — пароль и фактор. Отзыв других сессий работает в обоих режимах. Замена MFA доступна в режиме с MFA. Потеряв аутентификатор, войдите с резервным кодом, затем замените фактор. Старый фактор сохраняется до подтверждения нового; новые коды заменяют старые.

## Локальное восстановление и блокировка

Оператор хоста может выпустить одноразовый токен восстановления пароля:

```powershell
./scripts/docker.ps1 compose --profile tools run --rm tools python -m app.cli reset-token --username hr
```

Токен записывается в `.local/password-reset.txt`, действует 20 минут, вводится на экране «Восстановить пароль». Он не отключает MFA, не разблокирует аккаунт и не расширяет права. Эта операторская процедура отделена от приглашений в разделе «Доступ» и не заменяет проверку личности. Потеря всех факторов требует отдельной контролируемой процедуры; скрытого обхода MFA нет.

```powershell
./scripts/docker.ps1 compose --profile tools run --rm tools python -m app.cli block --username hr
```

Блокировка немедленно отзывает серверные сессии. Под `access` в разделе «Доступ» доступны обоснованные блокировка и разблокировка; пароль/MFA при разблокировке сохраняются.

## Дополнительно: отдельная учебная HTTPS-копия

Этот раздел необязателен для знакомства с проектом. Обычная установка выше открывается на `http://orgproekt.localhost:8080`; ключ Windows Hello не требуется. Команды ниже относятся к отдельно созданной копии из резервного архива. При скачивании с GitHub такая копия, её сертификат и резервный ключ автоматически не создаются. Сначала подготовьте архив по [инструкции резервного копирования](BACKUP_RESTORE_WINDOWS.md), затем создайте HTTPS-копию командами `restore-lab.ps1` и `Trust`, приведёнными ниже.

**Вход по ключу Windows Hello.** Обновите вкладку учебной копии. Один раз войдите обычным способом, затем нажмите на аватар справа вверху → **Моё пространство** → **Безопасность входа** → **Ключи доступа**. Введите понятное название, например «Рабочий ноутбук», и нажмите **Добавить ключ Windows Hello**. Подтвердите создание в системном окне Windows своим PIN или биометрией. Если прошло больше десяти минут после входа, сначала используйте поля текущего пароля и нового кода MFA над списком ключей. После подтверждения ещё раз нажмите кнопку добавления.

Дождитесь появления названного ключа в списке. Выйдите через меню профиля и нажмите **Войти по ключу доступа** на экране входа. Выберите сохранённый ключ и подтвердите в Windows. Используйте актуальный Edge или Chrome с настроенным Windows Hello. Если встроенный браузер не предлагает системное окно, откройте тот же HTTPS-адрес в Microsoft Edge. Резервный путь входа — прежний пароль и код аутентификатора. При потере устройства войдите с другого устройства привычным способом, в списке ключей нажмите **Отозвать** и **Подтвердить отзыв**. Отзыв закрывает другие серверные сессии этого аккаунта.

Ключи подключаются отдельно для каждого пользователя. PIN проверяет Windows на устройстве. Приложение хранит публичные данные ключа и историю операций. Для отдельных чувствительных операций при истечении свежести входа по-прежнему доступна форма повторного подтверждения с паролем и кодом.

Откройте [учебную копию OrgProekt](https://orgproekt-lab.localhost:8443/). Введите `auditor` и свой обычный пароль, нажмите **Продолжить**, затем введите свежий код из прежнего аутентификатора и нажмите **Подтвердить код**. Основной сайт находится по адресу [orgproekt.localhost:8080](http://orgproekt.localhost:8080/). У копии своя БД, очередь, обработчики и собственные сеансы входа. Изменения на каждом сайте сохраняются в его базе.

После остановки Docker Desktop включите Docker и запустите копию из PowerShell в папке проекта. Команда `Start` поднимает уже созданные контейнеры с сохранёнными данными. Для просмотра состояния замените `Start` на `Status`, для остановки на `Stop`.

```powershell
cd C:\Projects\OrgProekt
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\restore-lab-control.ps1 -HttpsTraining -Action Start
```

Параметр политики действует для запущенного процесса PowerShell. Быстрая проверка через браузер — открыть [страницу здоровья копии](https://orgproekt-lab.localhost:8443/api/health). Ожидается `{"status":"ok"}` через доверенное HTTPS-соединение.

Docker публикует только Caddy на `127.0.0.1:8443`. У Caddy есть отдельная входная сеть, а API, PostgreSQL, RabbitMQ, worker и scheduler работают во внутренней сети копии. Защищённое соединение проверено между браузером и Caddy. Развёртывание на выбранном сервере и TLS между серверными компонентами остаются отдельными этапами. Место установки и правила сетевого доступа выбирает владелец экземпляра.

Команда `Trust` устанавливает для текущей учётной записи Windows публичный сертификат `OrgProekt HTTPS training CA` после подтверждения Windows. Разрешённое DNS-имя издателя ограничено `orgproekt-lab.localhost`. Срок действия проверяйте в свойствах сертификата своего стенда. Ключ издателя создаётся в памяти одноразового контейнера на время одного выпуска. Закрытый ключ сервера хранится в защищённой `.local/https-training/`. При завершении использования стенда выполните `-Action Stop`, затем `-Action Untrust` той же командой управления. `Untrust` удаляет доверие только к сертификату данного стенда по его отпечатку. `Trust` возвращает доверие с подтверждением Windows. Для продолжения использования после истечения сертификата потребуется новый выпуск.

На другом ПК с готовым OrgProekt и подходящими образами для первого создания используйте проверенный архив и SHA-256 из доверенной квитанции. В PowerShell из папки проекта укажите свои значения вместо примеров.

```powershell
.\scripts\restore-lab.ps1 -HttpsTraining -Archive <архив.tar.age> -KeyFile <ключ.agekey> -ExpectedSha256 <проверенный-SHA256>
.\scripts\restore-lab-control.ps1 -HttpsTraining -Action Trust
```

Полное сравнение снимка и прав выполняется до запуска фоновых обработчиков копии. Используются два Compose-файла `compose.restore.yml` и `compose.https-training.yml` с отдельным именем проекта и приватным `restore.env`. Gemini в копии отключён.

Чтобы обновить для ключей доступа HTTPS-копию, созданную из прежних образов, в PowerShell из папки проекта выполните `.\scripts\update-training-passkeys.ps1 -Build`. Команда собирает отдельные образы API и интерфейса, кратко останавливает прикладные службы учебного стенда, создаёт зашифрованную копию его текущих записей, применяет добавочную миграцию 0008 и сверяет прежние строки. Выбранные образы сохраняются в приватном `training-release.env`, который использует команда `Start`. Для проверки на отдельной одноразовой БД используйте `.\scripts\test-training-passkeys.ps1` в PowerShell с Docker Desktop, Node.js, установленными frontend-зависимостями и Edge. Проверка использует порт 8444 и виртуальный ключ Chromium.

Параметр `-FullApi` запускает весь комплект серверных тестов перед проверкой входа в Edge. Без параметра скрипт проверяет API входа, ключей и прав доступа.

## Работа и обновление

Резервное копирование и восстановление проверяются на отдельном стенде. Создание собственного recovery-ключа и команды описаны в [BACKUP_RESTORE_WINDOWS.md](BACKUP_RESTORE_WINDOWS.md). После создания ключа обычная копия выполняется так: `./scripts/backup.ps1 -KeyFile .local/backup-keys/orgproekt.agekey`. Расписание Windows устанавливается отдельно; доступен режим ежедневно в 03:00 с хранением трёх последних автоматических копий в `backups/scheduled/`. Состояние установленного задания проверяется через `Get-ScheduledTaskInfo -TaskName OrgProekt-Backup` и `Get-Content .local/backup-operations/daily-status.json`. Восстановленная копия открывается на 8082 в отдельном профиле браузера, основной 8080 не заменяется. Новые локальные архивы нужно переносить во внешнее защищённое хранилище отдельно от ключа.

```powershell
./scripts/docker.ps1 compose stop
./scripts/docker.ps1 compose up -d
./scripts/docker.ps1 compose build
./scripts/docker.ps1 compose up -d
```

Volumes сохраняются при stop/rebuild. **Не используйте `down --volumes` для проекта `orgproekt`.** Перед будущими изменениями схемы необходим проверенный backup; автоматического rollback миграций пока нет. Не меняйте существующие пароли PostgreSQL только в `.env`: они были созданы при инициализации volume, требуется согласованная ротация роли.

Основные тесты:

```powershell
./scripts/docker.ps1 compose -f compose.yml -f compose.test.yml --profile tests run --rm tests
./scripts/e2e.ps1
./scripts/docker.ps1 compose --profile tools run --rm tools python -m app.cli verify-audit
```

E2E использует отдельные volumes `orgproekt-e2e_*`, отдельные аккаунты и порт 8081; основной стенд не изменяется. Снимки доступны в `docs/screenshots/`. Test traces/video отключены, чтобы не сохранять пароли и QR. `.local/e2e` содержит только временные тестовые факторы и исключён из Git.

## Частые ситуации

| Симптом | Действие |
|---|---|
| `docker` не найден в старом терминале | Использовать `scripts/docker.ps1`, который находит существующий пользовательский Docker Desktop |
| Docker daemon недоступен | Запустить Docker Desktop, дождаться готовности WSL engine |
| Порт 8080 занят | Найти использующее его приложение; менять порт вместе с `APP_ORIGIN` и публикацией Compose |
| Запрос отклонён по Origin | Открыть `http://orgproekt.localhost:8080`, проверить одинаковый origin UI/API; не отключать проверку |
| MFA-код отклонён | Проверить время и новый 30-секундный код; использованные коды повторно не принимаются |
| Команда требует повторного входа | «Моё пространство» → повторное подтверждение; затем повторить кадровую команду |
| 409 при назначении | Перечитать актуальную единицу; проверить пересечение дат и изменённую версию, не обходить ограничение |
| Уведомление ожидает | `compose ps`, затем `compose logs --tail=50 worker scheduler`; в настройках видны pending/failed, доступен повтор failed |
| Будущее событие без уведомления | Доставка запланирована на начало даты действия в настроенном часовом поясе |
| Ключ Gemini отсутствует | Это штатный учебный режим: поиск, сравнение и отчёты работают без внешнего ИИ; адаптер и ограничения описаны в README |

Не публикуйте вывод `docker compose config`, `docker inspect`, содержимое `.env`, `.local` и дампы БД: они могут содержать секреты. Логи проверять локально. Описанный запуск рассчитан на синтетические данные и loopback HTTP. Реальные кадровые документы и внешний доступ требуют отдельной подготовки серверного размещения; оставшиеся ограничения перечислены в README.
