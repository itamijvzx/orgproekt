# Разбор оставшихся зависимостей — 11 ноября 2026 года

Продолжение [исправлений аудита](SECURITY_FIXES_2026-11-11.md) и [разделения рабочих образов](CONTAINER_IMAGES.md). Исходная редакция — `35dfd84`; сверены отчёты пяти образов из [успешного запуска main](https://github.com/itamijvzx/orgproekt/actions/runs/42988874967). Задача — убрать ненужные уязвимые компоненты, сохранив данные, права и совместимость PostgreSQL. Это не заключение об отсутствии всех уязвимостей.

## Что исправлено

Из образа PostgreSQL через APT удалены GPG и его неиспользуемые зависимости, включая `libsqlite3-0`. Обратная зависимость SQLite в этом образе — `gpg`; PostgreSQL, pgvector и инструменты копирования SQLite не требуют. Проверка цифровых подписей пакетов APT сохранена: `gpgv` остаётся установленным. Шифрование копий OrgProekt использует age в другом образе.

Всего удалено 16 пакетов, число установленных системных пакетов уменьшилось **144 → 128**. Версии остальных пакетов не изменились. Сохранены PostgreSQL **17.11**, Debian bookworm, libc **2.36-9+deb12u14**, libxml2 и pgvector **0.8.7**. Перехода на другой выпуск ОС, пересборки сервера БД или смены правил сортировки нет. Удаление из верхнего слоя Docker не уменьшает размер уже существующих нижних слоёв; это уменьшение состава работающей системы, а не обещание экономии места на диске.

Добавлен `scripts/check_postgres_image.sh`, запускаемый в CI внутри готового образа без сети и базы. Он проверяет отсутствие пакетов и файлов SQLite, отсутствие GPG, наличие `gpgv`, entrypoint, gosu, PostgreSQL 17, pgvector и необходимых разделяемых библиотек. Старый образ с SQLite отклонён этим контролем; новый проходит. Правила Trivy и файл исключений не ослаблены.

## Что остаётся и почему

| Компонент | Проверенное основание и решение |
|---|---|
| **libxml2 в PostgreSQL**, включая CRITICAL CVE-2026-6653 | `ldd` подтверждает прямую зависимость сервера от `libxml2.so.2`. В Debian bookworm исправление отложено; простое удаление нарушает запуск БД. В SQL приложения не найдено использования XMLPARSE/XMLTABLE/xpath. Доступность уязвимого пути через приложение не подтверждена, но библиотека остаётся уязвимой. Не подменяем её пакетом из несовместимого выпуска Debian. Нужны поддерживаемое обновление либо отдельный проект миграции с проверкой сортировок и восстановления. [Debian](https://security-tracker.debian.org/tracker/CVE-2026-6653). |
| **MiniZip / zlib, CRITICAL CVE-2023-45853** | Debian указывает, что уязвимый contrib/minizip не собирается в бинарные пакеты zlib для bookworm. В проверенном образе отдельные minizip/libminizip не установлены. Это документированная неприменимость именно этого совпадения; другие предупреждения zlib автоматически ложными не считаются. Сырая запись сохранена. [Debian](https://security-tracker.debian.org/tracker/CVE-2023-45853). |
| **go-jose/v3 в Caddy, CVE-2026-116587** | Для v3 исправленной версии нет; уязвимый сценарий — разбор недоверенного RSA JWK. Caddy 2.11.9 зависит от smallstep/certificates 0.30.2 и go.step.sm/crypto 0.91.0, использующих v3. crypto 0.92.0 уже переходит на v4, но последний опубликованный стабильный certificates 0.30.2 по-прежнему требует v3. Замена только crypto не устраняет всю цепочку; сборка по текущему master certificates не была выбрана как стабильное исправление. В конфигурации OrgProekt не включены ACME-сервер и приём пользовательских JWK, административный API Caddy выключен. Это ограничение доступных путей, не исправление библиотеки. Сохраняем предупреждение до совместимого обновления. [Advisory](https://github.com/go-jose/go-jose/security/advisories/GHSA-mgcc-cww5-fp2q), [Caddy go.mod](https://github.com/caddyserver/caddy/blob/v2.11.9/go.mod), [certificates go.mod](https://github.com/smallstep/certificates/blob/v0.30.2/go.mod), [crypto 0.92.0](https://github.com/smallstep/crypto/releases/tag/v0.92.0). |
| **SQLite в backend/backup** | Это другой образ на Debian trixie. APT показывает обязательную цепочку `util-linux → liblastlog2-2 → libsqlite3-0`; удаление SQLite ломает базовые зависимости. Приложение хранит данные в PostgreSQL, но это не основание объявлять всю установленную SQLite безопасной. Пакеты не удалялись принудительно; предупреждения остаются. |
| **Kerberos/LDAP в PostgreSQL и клиенте backup** | Библиотеки входят в зависимости PostgreSQL/libpq. KDC/kadmind в образе не установлены; в тестовой конфигурации БД нет правил GSS/SSPI/LDAP. Многие сообщения сканера относятся к серверным компонентам Kerberos, однако это не доказывает неприменимость всех предупреждений библиотек. Удаление библиотек без пересборки PostgreSQL нарушает зависимости. Сохранены отчёты и обязанность обновлять их вместе с поставщиком. |
| **util-linux, systemd-библиотеки, ACL, ncurses, Perl, gzip и остальные записи** | Не удаляем необходимые системные пакеты ради снижения счётчика. Рабочие процессы приложения непривилегированы, без capabilities; parser дополнительно без сети и секретов. Для каждой записи нужна оценка конкретного вызываемого кода; полного доказательства недостижимости всех оставшихся путей эта работа не даёт. Новых общих исключений сканера нет. |

Для Caddy нельзя считать все функции PKI неиспользуемыми лишь потому, что обычный учебный сайт работает по HTTP: HTTPS должен оставаться доступным. Модули TLS/PKI не вырезались. Реальные секреты Gemini не добавлялись и внешние вызовы не выполнялись.

## Проверка и сохранность

Применены критерии [Identity & Access Engineer](references/agency-agents/engineering-identity-access-engineer.md): действующие серверные полномочия, отказ чужому отделу, отзыв прав и сохранность факторов входа. Это последовательная проектная проверка, не независимая сертификация.

- Новый стенд `orgproekt-dependency-review` использует собственные тома, внутреннюю сеть и случайные секреты. Серверные тесты создают только отдельные БД `orgproekt_test_*`.
- На новой базе: **167 passed, 5 skipped**, 226,82 с. Пропуски требуют age, отсутствующего в backend; само шифрованное копирование и восстановление проверены отдельно на настоящем backup-образе.
- Chromium с MFA: **6 passed** — приглашение/отзыв, согласование, выпуск PDF/DOCX, загрузка/сравнение/поиск, сохранение, чужой отдел и некорректный ввод. Просмотрены снимки выпуска отчёта 1440 px и управления правами 390 px; дизайн сохранён.
- Chromium на заново созданной базе без MFA: **6 passed, 1 ожидаемый skip** проверки MFA. Общий результат двух режимов — **12 passed, 1 skipped**. Проверены повторный пароль, сохранение сеанса и мобильный экран.
- Свежая шифрованная копия восстановлена на новом образе: **52 таблицы, 915 строк**, совпали схема/права, хэши файлов; цепочка **326** записей аудита валидна. **7** скопированных сессий отозваны только в копии.
- Дополнительный браузерный тест восстановленной копии: **1 passed**, вход auditor/it/access, изоляция, история доступа и совпадение байтов выпущенных файлов.

После проверок обновлён только контейнер основной PostgreSQL с прежним томом. На время сравнения остановлены API, worker и scheduler; после замены они запущены. До и после обновления совпали отпечатки **всех 52 таблиц и схемы**: сохранены **8 аккаунтов, 24 назначения прав и 47 редакций документов**. Файл секретов не изменился, цепочка аудита остаётся валидной (**326** событий). Совпадение файловых слоёв и рабочих настроек тестового/восстановленного образов проверено; различались только метки сборки Docker Compose. На текущем сайте `health: ok`; отдельный Chromium открыл форму входа без ошибок JavaScript и без входа в аккаунт.

Два временных Compose-проекта удалены вместе с их томами. Зашифрованная копия и прежний образ БД для отката сохранены; расписание и лимит автоматических копий не менялись. Приватные артефакты — `.local/dependency-review-20261111/`, восстановление — отдельный каталог `.local/restore-labs/`. В Git не включаются архив, ключи, данные, снимки рабочих документов или тестовые пароли.
