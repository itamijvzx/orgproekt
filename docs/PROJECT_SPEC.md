## Назначение и границы

Документальное сопоставление структуры, функций, назначений и версий организационных изменений. Факты имеют основание, период действия и время регистрации. Аудитор исследует и рекомендует; руководство принимает решения; HR регистрирует официальное исполнение. Нет автоматической оценки полезности людей, увольнения ИИ или вывода о нагрузке из числа функций.

Текущий срез 0–1: локальный Windows/Docker, синтетический реестр, личный вход + TOTP + резервные коды, серверные сессии, scoped API, схема, кадровые события, источники в виде вручную зарегистрированных выдержек, история, transactional outbox и уведомления. Полноценные оригиналы DOCX/PDF, RAG, Gemini/LangGraph, кейсы, согласование и отчёты относятся к следующим этапам. Статус реализации и фактические проверки — `PROGRESS.md`.

## Основной сценарий

1. Аудитор входит с MFA, выбирает дату, отдел и штатную единицу на схеме или в таблице.
2. HR в отдельной личной сессии регистрирует прекращение назначения с датой и выдержкой из основания. Система сохраняет прежние факты в событии и пересчитывает интервалы.
3. Отсутствие исполнителя — отдельное состояние от вакансии, упразднения и неполноты данных. Предупреждение имеет начало, источник и историю.
4. Outbox передаёт только ID события в RabbitMQ; Celery повторно проверяет текущие права адресата и создаёт одно уведомление.
5. HR оформляет временное или постоянное назначение. Период без покрытия заканчивается, история сохраняется.
6. Представитель финансов видит только разрешённый отдел, включая граф, списки, отдельные объекты и уведомления. Прикладной администратор не получает бизнес-данные.

## Неизменяемые принципы

Пустой поиск не доказывает отсутствие функции. Сходство текста не доказывает дублирование. Утверждение проекта не равно исполнению. Ответ не равен согласию. Согласие отдела не подменяет вывод аудитора. Изменение версии не наследует согласования. Облачный ИИ разрешается только для явно разрешённых синтетических материалов; ключ хранится исключительно на backend.

## Архитектура

React/TypeScript → Caddy (единый origin) → FastAPI → PostgreSQL/pgvector. Доменная транзакция одновременно сохраняет изменение, AuditEvent и OutboxRecord. Диспетчер → долговечная RabbitMQ → Celery worker → адресное уведомление. Модульный монолит, не микросервисы. Бизнес-данные не хранятся в localStorage. Zustand хранит только состояние представления в памяти.

Разработка начинается на Windows 11, затем тот же код переносится на Ubuntu 24.04. Текущий стенд доступен только через loopback HTTP и содержит вымышленные данные. Production заблокирован конфигурацией до реализации проверяемого TLS компонентов, bootstrap доступа и эксплуатационных проверок этапа 4.
