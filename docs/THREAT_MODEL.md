# Модель угроз

## Локальный учебный вход без MFA — 09.11.2026

По явному решению владельца новая локальная установка допускает вход по паролю для знакомства с вымышленными данными. Настройка `LOCAL_DEMO_MODE` по умолчанию в сервере false; генератор только новой `.env` явно включает true. Существующая конфигурация не меняется. Разрешены точные loopback HTTP-origin, ограничение порта Caddy на 127.0.0.1, проверка Host/Origin и CSRF; passkeys и внешний Gemini несовместимы с этим режимом. Это не защита от администратора, который сознательно опубликует локальный порт через туннель: такие развёртывания не входят в назначение режима.

Новая колонка сессии `local_demo` не заменяет `mfa_verified`: парольный учебный вход не помечается как пройденная MFA. После выключения режима его сессии не дают доступа к API/worker; действительные MFA-сессии сохраняют обычные правила. Проверки блокировки, сроков, отзыва, прав, актуального scope и повторного пароля остаются. TOTP-секреты, использованные шаги, резервные коды и роли не изменяются при учебном входе. Журнал различает такой вход. Для настоящих данных требуется MFA и отдельная подготовка размещения.

## Ключи доступа в учебной HTTPS-копии

Включение `PASSKEYS_ENABLED` требует настроенного HTTPS origin. Сервер берёт RP ID из этого origin. Для регистрации нужна активная сессия владельца с MFA и подтверждением не старше десяти минут. Одноразовый запрос живёт три минуты, привязан к назначению, origin и случайной защищённой cookie браузера. При регистрации он дополнительно привязан к сеансу. Получение запроса на этапе проверки удаляет запись в отдельной транзакции до проверки ответа. Истёкшие запросы чистятся. Сеть ограничивает размер входных данных, сервер ограничивает частоту попыток и число действующих ключей.

Yubico python-fido2 проверяет тип операции, origin, запрос, RP ID, признаки присутствия и проверки пользователя, а при входе также подпись. Сервер сверяет владельца непрозрачного user handle с владельцем действующего ключа, состояние аккаунта и счётчик подписей. Ключи со всегда нулевым счётчиком поддерживаются. После входа действуют общие отзываемые сессии, CSRF и актуальные права. Ключи можно подключать и отзывать только у себя. Эти действия записываются в аудит и личные уведомления. Восстановление снимка со схемой 0008 очищает незаконченные запросы WebAuthn в копии.

Обычный вход по паролю и MFA остаётся отдельным способом восстановления доступа к профилю. Для требований к аппаратному происхождению ключа понадобилась бы корпоративная политика аттестации. Текущий сервер запрашивает платформенный аутентификатор с локальной проверкой, принимает аттестацию `none` и хранит публичные данные. Реальный PIN, биометрию и выбор провайдера проверяет ОС сотрудника.

## Backup/restore — 31.10.2026

- Кража копии: age шифрует dump и необходимые внутренние ключи/credentials; внешний age-ключ отделён, Windows DACL ограничена владельцем/SYSTEM/администраторами. Открытый архив только в tmpfs. Recovery-копия ключа на другом носителе и физическое шифрование хоста ещё требуют настройки владельцем. tmpfs не доказывает отсутствие секретов в swap/VM memory snapshot.
- Подмена/повреждение: обязательный доверенный SHA ciphertext, полная аутентификация age до использования, внутренние SHA/allowlist/лимиты и запрет ссылок/traversal/дубликатов tar. Восстанавливаются только доверенные собственные dump: age public-key encryption не удостоверяет автора произвольного нового архива, SQL-определения исполняются при pg_restore.
- Перезапись основной БД: случайное имя отдельного проекта, новый volume/internal network, серверный restore_id и пустая БД; нет clean/drop/seed/миграций/переключателя на основную базу. Реальный main guard и отказ непустой копии проверены. Ошибка останавливает сервисы копии.
- Возвращение старых полномочий/токенов: сначала доказано совпадение данных/схемы/ACL/триггеров, затем только в копии отозваны перенесённые сессии/reset-токены/приглашения. Бизнес-права и отзывы сохраняются, текущие сроки продолжают проверяться. Старые пароль/MFA действуют, свежий вход обязателен.
- Внешние действия копии: internal network с проверенным запретом egress, только loopback 8082, worker/scheduler/RabbitMQ не запускаются, Gemini выключен. Cookie localhost не разделяются по порту: браузерную копию открывают в отдельном профиле.
- Минимизация QA: временные пароли/факторы берутся только из клона под guard, не выдаются stdout/trace/video, фиксированный QA-файл удаляется finally. Основные факторы/пароли/резервные коды не настраиваются автоматизацией. Host operator остаётся сильнее прикладных ролей; архив содержит все данные и требует соответствующей защиты.

Доказательства: `tests/test_backup.py`, `ops/backup.py`, `ops/restore_check.py`, `e2e/restore.spec.ts`, фактический `verify-source: unchanged`. Приложение новых HTTP backup/restore-команд не предоставляет. Это локальная проверка, не полное аварийное переключение/ASVS-аудит. [Windows/recovery-инструкция](BACKUP_RESTORE_WINDOWS.md).

## Управление доступом — 30.10.2026

- Единоличное повышение прав: access_admin только инициирует запрос другому лицу. Подтверждает независимый manager в требуемой области; инициатор/получатель исключены. Назначение технического администратора требует полной manager-области; новые технические/бизнес-роли разделены по аккаунтам. Запрос от потерявшего полномочия инициатора не утверждается.
- Кража/повтор приглашения: случайный код 32 байта, ограниченный срок, SHA-256 для поиска, зашифрованная локальная копия, одноразовая активация под блокировкой. Нет кода в URL/localStorage/списках/аудите; выдача отдельно журналируется и требует reauth. Отмена, срок и актуальные полномочия пригласившего проверяются снова. Внешняя доставка вне development/test закрыта. Получатель не получает сессию или роли при активации.
- Отзыв и старые результаты: центральная политика проверяет актуальные назначения/отзывы на сервере. Изменение прав завершает все сессии; блокировка действует на обычный вход и предварительную MFA-сессию. Разблокировка/сброс пароля не отключают MFA и не возвращают прежние сессии. Тест включает ранее доступные отчёт/PDF/DOCX и источники после отзыва.
- Гонки/повторы: версия, квитанция команды, locks и повторная проверка полномочий после ожидания; параллельные активация/решения не дублируют эффект. Ошибка обязательного аудита откатывает команду. Факты отзыва/квитанции защищены от UPDATE/DELETE; исходные назначения сохранены.
- Минимизация данных: администратор видит технический каталог, статус MFA и названия областей, но не бизнес-содержимое или секреты входа. Manager получает только допустимую очередь запросов. Запрещённый объект скрывается через 404, без входа — 401; меняющие запросы требуют Origin/CSRF и свежего подтверждения входа.
- Тестовая изоляция: сброс счётчика попыток — только CLI в disposable e2e с env/приватным guard/проверкой фиксированных тестовых аккаунтов; публичного endpoint нет. Обычные лимиты не изменены. Утрата всех факторов и административное MFA-recovery остаются отдельной задачей, публичного обхода нет.

Доказательства: `test_access_management.py` (в том числе конкурентность, replay, будущие/истёкшие назначения, откат и отрицательный guard), `AccessWorkspace.test.tsx`, `e2e/access.spec.ts`. Инженерные ориентиры: [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html), [OWASP Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html). Это проверка выбранных механизмов, не полный аудит ASVS. Оператор хоста/DB root сильнее прикладного администратора. TLS/зашифрованное хранилище/backup и рабочая почтовая доставка ещё не завершены.

## Добавление отчётов — 30.10.2026

- Обход через экспорт: для списка, детали, редакции, текущего исполнения и каждого файла заново проверяются активный аккаунт, роль, область и явная адресность; чужой объект — 404. Доступ к отчёту не является приглашением в предложение или правом на чужой источник.
- Утечка через выписку: снимок строится из одного отдела; общие межотдельские основания, чужие разделы, личные заметки и закрытые поля квалификации исключаются. Свободный текст автора требует отдельной проверки reviewer; автоматическая классификация всех конфиденциальных упоминаний не заявляется.
- Подмена/повтор выпуска: отдельный reviewer, свежая reauth, проверка хеша редакции, оптимистическая версия, row/advisory locks, неизменяемые редакции и квитанции. Сбой аудита откатывает всю команду. После формирования файлов проверяется отзыв сессии и текущие права участников; повтор запроса не пересоздаёт файл.
- Незаметное изменение истории: выпущенный Report, содержание, manifest и байты защищены runtime-привилегиями/триггерами. Новая редакция источника и исполнение не меняют выпуск. Журнал выдачи и хеш файла проверяются перед ответом.
- Рендеринг не загружает внешние изображения или адреса: текст XML/HTML экранируется, ссылки строятся сервером на собственные сохранённые anchors. Размер снимка ограничен; полноценный нагрузочный тест больших отчётов не выполнен.
- Скачанную копию можно изменить или переслать вне системы; это не ЭЦП/DRM. Администратор хоста/БД сильнее прикладных ограничений. Шифрованное хранилище и backup/restore остаются незавершённой инфраструктурной частью этапа 4.

Доказательства: пять интеграционных сценариев `test_reports.py` и браузерный `reports.spec.ts` (состав, отрицательные права, отзыв в ходе рендеринга, откат аудита, повтор, конфликт, запреты UPDATE/DELETE, оба формата).

Этап 3: объект предложения не открывается по одному совпадению отдела — требуется актуальная бизнес-роль и авторство/адресное участие в разрешённой версии. Межотдельские разделы выдаются частично; общий заголовок и глобальные основания скрываются при неполной области. Поиск проверяет только разрешённую проекцию. Приватные заметки доступны только их автору и не публикуются при отправке. Новая версия не наследует согласие; автор не утверждает свой проект и исполнитель не проводит независимую проверку собственного исполнения. Управленческое решение и исполнение требуют свежей повторной аутентификации. Отозванные права проверяются в запросах, уведомлениях и перед доставкой worker.

Кейс, неизменяемая запись действия, квитанция идемпотентности, аудит и адресный outbox записываются одной транзакцией. Очередь содержит только ID. Технические ошибки не логируют текст сообщений/документов. Владелец хоста может явно создать отдельные синтетические учебные аккаунты workflow-demo; эта команда не является HTTP-обходом и не меняет существующие роли, пароли или MFA. Статус «исполнено» фиксирует документально обоснованное подтверждение HR, не гарантирует истинность введённых сведений и требует отдельной аудиторской проверки.

Дополнение этапа 2: документы считаются недоверенными данными. ZIP-path/DTD/entities/macros/active PDF/embedded files блокируются, внешние ссылки не загружаются. Оригинал помещается в закрытую БД, не в webroot; скачивание доступно после структурной проверки, с attachment/nosniff/CSP sandbox. Child parser имеет лимиты CPU/RAM/времени и очищенную среду без ключей/DSN. Это не антивирус и не доказанная защита от всех уязвимостей библиотек; production-песочница и независимый hardening остаются задачами этапа 4.

Оригиналы bytea, метаданные, audit и job коммитятся вместе; они входят в PostgreSQL-backup, не требуют несогласованной копии отдельного uploads-каталога. Приложение не перезаписывает/не удаляет оригиналы и извлечённый текст. Worker использует lease и проверки scope/сессии до чтения и до фиксации результата. Prompt injection не исполняется парсером; у адаптера Gemini нет tools, ID/цитата валидируются, бизнес-данные по умолчанию запрещены для отправки. Семантическая верность ответа требует проверки человеком.

Ценности: секреты входа/MFA, кадровые сведения, источники, корректность периодов и неизменяемая история. Границы: браузер → единый origin Caddy → API → PostgreSQL; очередь и worker; отдельный владелец хоста. Стенд 0–1 предназначен только для синтетических данных на loopback.

| Угроза | Реализуемая мера | Проверка/ограничение |
|---|---|---|
| Подбор пароля и MFA | Argon2id 64 MiB/3 прохода/1 поток, солёные хеши; PostgreSQL rate buckets; нейтральные ошибки | Ограничение на источник/челлендж, без блокировки аккаунта по чужому логину; production proxy/rate policy требует отдельной настройки |
| Кража/повтор сессии | Случайные 256-битные значения, в БД SHA-256, HttpOnly/SameSite, срок 8 ч, preauth 10 мин, ротация после MFA | Отзыв/блокировка на каждом запросе; токен не в localStorage |
| CSRF | Точное совпадение Origin для изменяющих запросов + привязанный к сессии CSRF | JSON API не принимает изменяющий GET |
| Секрет MFA в БД | Fernet, отдельный ключ среды; коды 96-битной энтропии, хеши, одноразовое погашение | TOTP не является phishing-resistant; passkeys не заявлены |
| Восстановление обходит MFA | Одноразовый 20-минутный токен, сохраняет MFA/блокировку/права, отзывает сессии | Локальная контролируемая доставка владельцем, не публичная почта |
| IDOR / чужой отдел | Общие scoped queries + объектные проверки до изменения/выдачи | Проверяется API/граф/источник/уведомление; будущие модули отдельно |
| Дубли и конкуренция | Idempotency fingerprint, lock строки, expected_version, GiST exclusion, outbox unique | Повтор с другим телом отклоняется; exactly-once не обещается |
| Потеря обязательного аудита | Изменение + аудит + outbox в одной транзакции | Ошибка аудита откатывает бизнес-эффект |
| Подмена журнала | Роль app без UPDATE/DELETE, триггер, HMAC-цепочка, отдельная seal | Root с ключом может подделать; копию seal нужно хранить вне БД/хоста |
| Утечка секретов в логи | Не логировать request body/DSN/токены; безопасные коды ошибок, no access logs | Проверка сборки и репозитория перед публикацией |

Production пока намеренно не запускается. TLS PostgreSQL/RabbitMQ, зашифрованные тома/backup, доверенный CA ноутбука, полноценные приглашения и управление бизнес-правами — незакрытые задачи перед реальными данными. Docker сам не шифрует диск. Не меняем разделы владельца и не публикуем порт БД/очереди.
# Выбор учебного аккаунта — 30.10.2026

Операторский `workflow-demo --username demo_manager` выбирает один аккаунт из жёстко заданного списка, с прежней проверкой development и синтетического набора. Это не публичный API выдачи прав. Добавляются только новый пользователь, его manager-права на пять учебных отделов и запись security-аудита; пароль создаётся существующим безопасным генератором, хешируется прежним Argon2 и записывается исключительно в новый приватный файл. Существующие аккаунты/права не обновляются, повтор отказывается от перезаписи даже при отсутствии файла паролей. MFA пользователь подключает самостоятельно. Тесты охватывают выбор одного/двух аккаунтов, неизвестное имя, коллизию существующего аккаунта/файла, запрет других режимов и отсутствие синтетического стенда.
